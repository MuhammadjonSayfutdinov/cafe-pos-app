# CAFE POS APP — AI KONTEKST (yangilangan: 2026-10-26)

Bu fayl AI agentlar (Gemini, Claude, Cline va boshqalar) uchun loyihaning yagona
haqiqat manbai. Har bir vazifadan oldin shu faylni va PROGRESS.md ni o'qing.
Hozirgi vazifa va ma'lum xatolar ro'yxati PROGRESS.md da.

---------------------------------------------------------------------------
1. LOYIHA
---------------------------------------------------------------------------
Kafe uchun POS tizimi: ofitsiant, kassa, oshxona (KDS), ombor, admin, statistika
va mijozning QR-menyusi.

Stek: React 19, Vite, Tailwind CSS 4 (CDN emas, npm orqali), JSX.
Ma'lumotlar: hozircha faqat brauzer localStorage (backend yo'q).
Til: dastur interfeysi va muloqot faqat O'ZBEK tilida.

MUHIM CHEKLOV: localStorage bitta qurilmaga bog'liq. Qurilmalararo sinxron
(ofitsiant <-> oshxona) va mijozning QR buyurtmasi faqat backend qo'shilgach
haqiqatan ishlaydi (PROGRESS.md, 3-bosqich).

2. AI AGENT UCHUN QOIDALAR
---------------------------------------------------------------------------
1. FAQAT SO'RALGAN fayl va funksiyalarga teging. Boshqa kodni qayta yozmang,
   qayta formatlamang, qayta nomlamang.
2. O'zgartirilayotgan funksiyani TO'LIQ yozing (ichida "// ... qolgan kod"
   qoldirmang), lekin tegilmagan funksiyalar va butun faylni qayta yozmang.
   Natija: diff kichik va o'qiladigan bo'lsin.

4. Bitta vazifa = bitta commit. Xabar formati: "<bosqich raqami>: <vazifa>".
5. Maxfiy ma'lumotni (token, PIN, parol, .env) hech qachon commit qilmang.

     quantity (qty emas), subTotal (subtotal emas), total (finalTotal emas),
     waiter (waiterName emas), serviceFee (serviceFeePercent emas).
   O'qishda eski nomlarni qo'llab-quvvatlang (eski ma'lumotlar buzilmasin).
7. Sanani matn sifatida solishtirmang (toLocaleDateString() bilan ==).
   Vaqt filtri uchun createdAt (millisekund) dan foydalaning.
8. Pulni butun so'mda hisoblang. Jami summani qo'lda qayta yozmang: yagona
   hisob funksiyasi (src/utils/orderTotals.js -> calcOrderTotals) bo'lsa,
   shundan foydalaning; hali yo'q bo'lsa, uni yarating.
9. Omborni (xomashyo) ayirish faqat BITTA joyda bo'ladi. Qaysi joyda
   ekanligi PROGRESS.md dagi "Qarorlar" bo'limida yozilgan. Boshqa joyda
   qayta ayirmang.
10. Himoya: massivni .map/.filter/.reduce qilishdan oldin
    Array.isArray(x) ? x : [], sonlarni Number(x || 0) bilan oling,
    obyektni to'g'ridan-to'g'ri JSX ichida chiqarmang (React Error #31).
    Bu xatoni YASHIRADI, tuzatmaydi: asl sababni ham toping.
11. Interfeys Telefon, Planshet va Kompyuterga moslashuvchan (sm:, md:, lg:)
    va dark: klasslari bilan kunduzgi/tungi rejimda ishlashi shart.
12. alert/confirm/prompt o'rniga modal yoki bildirishnoma (toast) ishlating
    (yangi kodda).
13. Vazifa oxirida qisqa hisobot bering: o'zgargan fayllar, nima qilindi,
    qanday sinab ko'rish kerak.

4. MA'LUMOTLAR (localStorage kalitlari, App.jsx da useSticky orqali)
---------------------------------------------------------------------------
pos_menu          taomlar         pos_orders       buyurtmalar
pos_categories    kategoriyalar   pos_tables       stollar
pos_users         xodimlar        pos_calls        ofitsiant chaqiruvlari
pos_inventory     ombor           pos_inv_logs     ombor tarixi
pos_customers     mijozlar (bonus) pos_expenses    xarajatlar
pos_audit_logs    audit jurnali   pos_service_fee  xizmat foizi (10)
pos_cafe_name     kafe nomi       pos_theme        dark/light (boolean)
pos_override_enabled  admin PIN himoyasi yoqilganmi (boolean)

pos_menu (taom):
  { id, name, category, is_available, variants: [{id, name, price}],
    recipe: [{inventoryId, name, unit, qty}] }
  Narx manbai: variants[n].price. Retseptda yangi kodda faqat
  inventoryId va qty ishlating (productId, amount eski nomlar).

pos_orders (buyurtma):
  { id (string, Date.now()), createdAt (ms), table, waiter,
    items: [{cartItemId, id, name, baseName, variantName, price,
             quantity, note}],
    subTotal, serviceFee (foiz), serviceFeeAmount, discount, total,
    status, paymentMethod, paymentDetails, time ("14:30"), date (matn) }
  "date" va "time" faqat ko'rsatish uchun; hisob-kitob uchun createdAt.

Statuslar (haqiqatda ishlatiladiganlar):
  'Yangi' -> 'Tayyorlanmoqda' -> 'Tayyor' -> 'Yetkazildi' -> "To'langan"
  Qo'shimcha: 'Qarz', 'Arxiv'. 'Bekor qilindi' hozircha kodda ishlatilmaydi.
  Yangi holat qo'shsangiz, constants fayliga kiriting (qo'lda yozmang).

pos_users (xodim): { id, name, role, pin, canSeeSales? }
  role: 'admin' | 'warehouse' | 'cashier' | 'waiter' | 'kitchen'
  PIN: admin va warehouse uchun 6 xonali, qolganlari uchun 4 xonali.
  Ikki xodimda bir xil PIN bo'lishi mumkin emas (LockScreen PIN bo'yicha
  xodimni topadi).
  Oxirgi yagona adminni o'chirib bo'lmaydi.

pos_inventory: { id, name, unit, quantity, minLimit, costPrice, updatedAt }
pos_inv_logs: ombor amallari, turlari: 'kirim', 'chiqim_avto', 'spisanie'
pos_customers: { name, phone, bonusBalance, ... } (CRM, bonus/keshbek)
pos_audit_logs: { id, date, action, details, userName, role }
pos_calls: [{ id, table, time }]

5. BIZNES QOIDALARI (kutilgan xatti-harakat)
---------------------------------------------------------------------------
- Kategoriya nomi o'zgarsa, menyudagi taomlarning category maydoni ham
  yangilanadi. Taomi bor kategoriyani o'chirishda ogohlantirish + audit log.
- To'lov turlari: Naqd (qaytim bilan), Plastik, Click/Payme, Aralash
  (summalar yig'indisi jamiga teng bo'lishi shart), Qarz (mijoz ismi VA
  telefoni majburiy).
- Chegirma jami summadan oshmasligi kerak; katta chegirma admin PIN so'raydi
  (isOverrideEnabled yoqilgan bo'lsa).
- Oshxona: 0-10 daq yashil, 10-20 sariq, 20+ qizil; izoh (note) yorqin.
- Ombor: quantity <= minLimit bo'lsa "Kam qoldi" belgisi.
- Statistika: faqat "To'langan" (va alohida blokda 'Qarz') hisoblanadi.
- Xavfsiz amallar (o'chirish, zaxira tiklash, bazani tozalash) admin PIN
  tasdig'ini talab qiladi.
